# Project Overview: MediatorOS - A MicroPython Integrated Kernel

MediatorOS is a minimal 32-bit x86 operating system kernel that integrates the MicroPython runtime. The project aims to provide a bare-metal environment where Python code can be executed. It features a custom build system, a minimal C standard library implementation, and a custom Hardware Abstraction Layer (HAL) for MicroPython to interact with the OS. The OS is bootable via GRUB and runs in QEMU.

**Key Technologies:**
*   **Kernel:** C and NASM assembly for a 32-bit i686-elf target.
*   **MicroPython:** Integrated as a static library, providing a Python execution environment on the kernel.
*   **Build System:** Makefiles are used for orchestrating the build process, including cross-compilation.
*   **Bootloader:** Uses GRUB via a Multiboot header in the startup assembly.
*   **Emulation:** QEMU for running the OS.
*   **Toolchain:** `i686-elf-gcc`, `nasm`, `i686-elf-ar`, `i686-elf-ld`.

**Architecture:**
The project is structured around a core MediatorOS kernel (`mediator/` at `MediatorOS-0.12/mediator`) and a MicroPython port (`micropython/ports/mediator` at `MediatorOS-0.12/micropython/ports/mediator`).

*   **MediatorOS Kernel (`mediator/`):**
    *   **Bootstrapping:** `boot/stage0.asm`, `boot/stage1.asm` and the dynamically generated `startup.asm` handle initial CPU setup, GDT, stack initialization, BSS clearing, and protected mode transition, eventually calling the C `main` function.
    *   **Main Entry:** `kernel/kernel.c` contains the `main` function, basic VGA text mode output, and the call to `micropython_main()` to start the MicroPython runtime. It also includes `bios_screen.h` for an initial display.
    *   **Custom Libc:** `libc/string.c` provides essential C standard library functions (`memcpy`, `memset`, `memmove`, `memcmp`, `strlen`, `strcmp`, `strncmp`, `strchr`) required for the freestanding environment.
    *   **Linker Script:** `linker.ld` (dynamically generated by `write_linker_script.py`) defines the memory layout of the kernel, including sections for code, data, and BSS.
*   **MicroPython Port (`micropython/ports/mediator/`):**
    *   **Configuration:** `mpconfigport.h` configures MicroPython's build options for MediatorOS, including enabling the compiler, garbage collection (GC), and REPL. It disables `sys` module features, and explicitly disables `io` and `builtins.open`. It defines port-specific types (`mp_uint_t` as `uintptr_t`) and configures a dedicated Python stack (4KB).
    *   **Hardware Abstraction Layer (HAL):** `mphalport.c` provides implementations for MicroPython's HAL functions. `mp_hal_stdin_rx_chr` is a stub, and `mp_hal_stdout_tx_strn` implements console output by calling the kernel's `print_string` and returning the number of characters written.
    *   **Build Output:** Compiles MicroPython core and port-specific C files into `libmicropython.a`, which is then linked into the main kernel binary.
*   **Tooling/Generation Scripts (top-level Python files):** These scripts automate the generation of critical build artifacts:
    *   `generate_bios.py`: Creates `mediator/kernel/bios_screen.h` with an initial boot screen message.
    *   `write_linker_script.py`: Generates the `i686-elf.ld` linker script.
    *   `write_startup_asm.py`: Generates the initial assembly bootstrap (`startup.asm`) for the kernel.
    *   `write_c_startup.py` and `write_file_content.py`: (Not detailed, but likely related to other code generation tasks).

# Building and Running

The project uses a `Makefile` in the `mediator/` directory as its primary build system.

**Prerequisites:**
*   A `i686-elf` cross-compiler toolchain (gcc, binutils, etc.) is expected to be installed and available in the `PATH` at `$(HOME)/cross-compiler/opt/bin`.
*   `nasm` assembler.
*   `grub-mkrescue` for creating bootable ISOs.
*   `qemu-system-x86_64` for running the OS in an emulator.

**Build Commands:**

1.  **Clean the build artifacts:**
    ```bash
    make -C mediator clean
    ```
2.  **Build the entire MediatorOS kernel and MicroPython library:**
    ```bash
    make -C mediator all
    ```
    This command will:
    *   Compile the MediatorOS kernel C and assembly files.
    *   Compile the custom `libc` implementations.
    *   Recursively build the MicroPython port (`micropython/ports/mediator`) into `libmicropython.a`.
    *   Link all components together, ensuring `libmicropython.a` is linked before `libc.a` to correctly resolve standard C library functions, producing `build/kernel.bin`.

**Running the OS:**

1.  **Build the bootable ISO image:**
    ```bash
    make -C mediator iso
    ```
    This command relies on a successful `make all` and then uses `grub-mkrescue` to create `mediator.iso`.
2.  **Run the OS in QEMU:**
    ```bash
    make -C mediator run
    ```
    This command relies on a successful `make iso` and then executes `qemu-system-x86_64 -cdrom mediator.iso`.

# Development Conventions

*   **Cross-Compilation:** The project is strictly designed for cross-compilation to the `i686-elf` target.
*   **Freestanding Environment:** The kernel and MicroPython port operate in a freestanding C environment, necessitating custom implementations for standard C library functions.
*   **MicroPython Porting:** Adheres to MicroPython's porting guidelines for HAL implementation and configuration, using `mpconfigport.h` for build options and `mphalport.c` for hardware interactions.
*   **Code Generation:** Python scripts automate the generation of critical assembly files, linker scripts, and C header files, allowing for dynamic configuration and a streamlined build process.
*   **Debugging:** `CFLAGS` include `-g` to embed debug information in the compiled binaries.
*   **Error Handling:** Compiler warnings are treated as errors (`-Werror`) to maintain high code quality.
*   **Python Stack:** MicroPython uses an internally managed Python stack (`MICROPY_ENABLE_PYSTACK`) instead of `alloca` for robust operation in the bare-metal environment.
